02 · Architecture

Four layers, one rule that isn't optional

The scheduling UI never reaches into storage or the PDF engine on its own — every access to persistence or card generation is required to pass through the domain/state layer. That's not a convention left to discipline; it's enforced by an ESLint rule that fails the build.

01UI layerapp/ routes + components/ — forms, agenda builder, attendee list, live preview. Reads and writes state only through hooks.
02Domain / statelib/store/ — meeting, agenda, and attendee operations; owns every validation rule (BR2.3, BR3.2–3.4) and the render/export delegating methods the UI actually calls.
03Persistencelib/persistence/ — an IndexedDB/localStorage adapter behind a narrow save/load/clear interface. Handles quota limits, private-browsing restrictions, and corrupted stored data without crashing the app.
04Card enginelib/card/ — pure functions from validated domain data to a rendered PDF and QR code. No DOM access, no store access; independently testable.
✕ForbiddenAny component in components/ or app/ importing lib/persistence/*, lib/card/*, @react-pdf/renderer, or qrcode.react directly — blocked by .eslintrc.json, CI-blocking.

Stack

Next.js 16.3.5 · App Router React 18.3.1 + TypeScript (strict) Tailwind CSS @react-pdf/renderer 4.9.0 · PDF export qrcode.react 3.1.0 · QR generation idb-keyval 6.2.1 · browser storage lucide-react · icons Vitest + Testing Library · unit/component Playwright · 5-browser E2E Vercel · hosting, zero backend

03 · What broke in a real browser

Two bugs, invisible to 53 passing unit tests

Every one of the 53 Vitest component tests was green throughout. Both of these defects only exist because jsdom — the browser simulator those tests run in — doesn't enforce a Content-Security-Policy the way a real browser does. Playwright's five-browser E2E pass is what caught them, both diagnosed with a disposable script that just listened for console and page errors.

BUG 01

The app never rendered — blank page, every real browser

fixed
SymptomMeetings List never appeared. First E2E assertion timed out on a completely blank page.
CauseNext.js's own inline hydration bootstrap scripts carry no nonce attribute unless a Server Component reads the per-request nonce via headers() — nothing in app/layout.tsx did that, so the CSP's script-src 'nonce-…' directive silently blocked the app's own startup scripts.
FixMade RootLayout an async Server Component reading (await headers()).get('x-nonce') — the read alone activates Next's automatic nonce propagation to every script tag it renders.
BUG 02

PDF export failed silently after the first fix landed

fixed
SymptomWith hydration fixed, the flow ran clean through meeting creation and save — then export threw at the last step.
Cause@react-pdf/renderer's font-layout engine compiles a WebAssembly module at runtime. The CSP granted neither 'wasm-unsafe-eval' in script-src nor data: in connect-src, so the browser blocked WebAssembly.instantiate() outright.
FixAdded exactly those two CSP grants in proxy.ts — deliberately narrower than 'unsafe-eval', permitting WASM compilation only — and upgraded the library 3.4.4 → 4.9.0 for a clearer failure signal along the way.

04 · Continuous integration

Four gates before merge, one gate after

All four pre-merge checks run in parallel — GitHub branch protection requiring every one as a status check gets the same blocking guarantee as a sequential pipeline, with faster feedback.

.github/workflows/ci.yml
JobTriggerChecks
gitleaksevery PRSecret scanning across the PR diff
lint-typecheck-testevery PReslint, tsc --noEmit, full Vitest suite with the 80% coverage floor enforced
codeqlevery PRGitHub CodeQL default setup, JavaScript/TypeScript
dependency-auditevery PRnpm audit --omit=dev --audit-level=high
e2e-smokepush to main, post-mergeFull Playwright happy-path suite; needs lint-typecheck-test first; uploads the HTML report as an artifact
Recurring jobs
FileSchedulePurpose
scheduled-audit.ymlweekly (Mon 06:00 UTC) + manualnpm audit --omit=dev, independent of PR activity
dependabot.ymlweeklynpm dependency PRs, dev-dependencies grouped into one PR

No deploy secret lives in GitHub Actions at all — Vercel's GitHub App integration deploys independently of these workflows once connected. The only credential any job uses is the auto-provisioned GITHUB_TOKEN, scoped to contents: read and security-events: write.
